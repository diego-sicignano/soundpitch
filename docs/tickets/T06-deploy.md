## Goal

A public URL that works without a login, stays up until the end of judging, makes no model call and cannot run up the bill.

## Steps

1. *(done)* `backend/tests/test_smoke.py` and `backend/app/smoke.py` (`python -m app.smoke <base-url>`).
2. *(done 2026-10-20)* Built and run on Docker 29.6.2 with `--read-only --cap-drop ALL`, with and without network; smoke check passed; result in `docs/DEPLOY.md`.
3. **With the owner's approval of the resources and their cost:** create the resource group, the Container Apps environment and the container app (Consumption only, external ingress, port 8000, minimum 0 and maximum 1 replica, `SOUNDPITCH_TRUST_PROXY=1`), from the image. Check the current `az containerapp` documentation first; write the commands that were run into `docs/DEPLOY.md`.
4. Run the smoke check against the public URL; open it in a clean browser window.
5. Put the URL in `README.md` and `docs/submission/PITCH.md`. Calendar reminder: **do not delete or stop it before 11 Nov 2026, 08:59 Italian time.**

## Out of scope

A live model or its ledger in the public path (D12), a custom domain, autoscaling rules beyond the replica limit, a database, Functions or Logic Apps.

**State checked read-only on 2026-10-20.** The replay file holds 26 replies and covers 30 of 30 requests (T11 finished, nothing in flight); the image built and passed the smoke test read-only, as UID 10001, without capabilities and without network. Azure: one resource group in Italy North (Foundry account S0 with the deployment `soundpitch-mini`, a Log Analytics workspace, an Application Insights component, an action group), a monthly budget of 5 that only alerts, a Pay-As-You-Go subscription with no spending limit, and the owner has Owner on it. `Microsoft.App` is not registered, no Container Apps resource exists (so the monthly free grants are unused), no Speech resource exists.

**Recommended host: Azure Container Apps, Consumption only, scale to zero, one replica at most, in its own resource group** (`rg-soundpitch-demo`, so cleanup cannot touch the Foundry resources).
- App: 0.25 vCPU and 0.5 GiB (the smallest valid pair), minimum replicas 0, maximum replicas 1, external ingress on port 8000, `SOUNDPITCH_LLM=replay`, no secrets, no volume, no registry credentials. **Local load check, not a capacity claim.** On 2026-10-20 an earlier run reported about 50 MiB and 200 parallel session requests in 9.8 s (median 0.97 s), no error; its script was not kept, so those figures cannot be reproduced exactly and are not relied on. Re-measured on 2026-10-21 with the image built from the repository (Docker Desktop on Windows, `--cpus 0.25 --memory 512m`, `--read-only`, non-root, one run each, script not committed): 200 parallel requests over the 30 demo sessions, empty cache, 0 errors, 0.84 s in all (median 0.51 s); the same again with the cache warm, 0 errors, 0.70 s; 200 sessions that each differ in speech rate so none is cached, 0 errors, 2.79 s (median 2.54 s). Memory: 41 MiB idle, 64 to 73 MiB afterwards. This is a laptop CPU with a quota, not an Azure vCPU, with no network between client and server and no cold start; it shows the replay path does not fall over under a burst on one core quota, and nothing about Container Apps or about public traffic.
- Environment: type "Consumption only (legacy)" (`--enable-workload-profiles false`) with `--logs-destination none`. The documentation says of this type "There's no cost associated with the Container Apps environment" and that a workload-profiles environment pays a management fee only when a Dedicated profile, a private endpoint or planned maintenance is used. No Dedicated or Flexible profile, no private endpoint, no maintenance window, no registry and no Log Analytics are created. If the legacy type cannot be created, the fallback is the default environment with only its Consumption profile, same settings.
- Free grants (per subscription and calendar month, documented): 180,000 vCPU-seconds, 360,000 GiB-seconds and 2 million requests, equal to 200 replica-hours a month at this size. Modelled judge traffic uses 3 hours (20 visits), 20 hours (120 visits of 10 minutes) or 125 hours (600 visits of 15 minutes) in the whole window: no charge beyond the grants. Kept awake 24/7 the cost would be about USD 1.5 in October and USD 1.9 in November. A visit makes 15 to 40 requests.
- Not guaranteed: replica counts are a target, not a guarantee; budgets only alert; Azure's real bill arrives 8 to 24 hours late.

**The "Environment" meters.** The public price list (Retail Prices API, read 2026-10-20) has three meters with productName `Azure Container Apps`, skuName `Environment`, skuId `DZH318Z0B0NC/00DR`, USD 0.13 an hour in Italy North: `Environment Management Hour` (meterId 890fee2d-e58e-5a18-a7ac-3134f51b3d24), `Environment Planned Maintenance Hour` (b2bc9bdf-62bb-525e-be91-69f2e169831b) and `Environment Private Endpoint` (22d94d33-7e97-59a7-b7f9-f94f72c01456), effective 2026-09-01 to 2026-10-31 (in other regions USD 0.10 to 0.143, some without an end date). The consumption meters are a different skuName (`Standard`). No official page, announcement or documentation change defines these three meters (the public docs history shows no change to the billing article after 2026-03-25). The documentation describes only one management meter, "Dedicated Plan Management" (USD 0.10), charged for a Dedicated profile, a private endpoint or planned maintenance: the three new names match those three causes one to one, so the most probable reading (an inference, not a statement) is a split of that meter by cause, which this architecture does not trigger. If instead they applied to every environment they would add USD 0.13 an hour, about USD 3.1 a day and USD 64 over the window. **Cost gate:** deploy on 22 Oct, read Cost Analysis on 23 or 24 Oct (data 8 to 24 hours late) and look for any `Environment` meter line; if one appears, delete the environment at once (loss about USD 3 to 6) and move to the fallback below.

**Fallbacks, in order of cost.** (1) Render Free: USD 0, no Azure account, but 0.1 CPU and 512 MB, spin-down after 15 minutes without traffic and about a minute to wake with a loading page, 750 free hours a month and a bandwidth cap that suspends all free services if exceeded; it is not confirmed that Free accepts an image-backed service or that a public ghcr.io image pulls without credentials, a deploy freeze for free services was reported on its status page on 2026-10-14, and it hosts nothing on Azure. (2) Azure App Service on a Linux B1 plan: USD 0.018 an hour, about USD 8.8 for the window, fixed and not raised by traffic; not approved.

**Cold start.** With minimum replicas 0 the replica stops after about 300 seconds without traffic, and the next visitor waits for the image pull and start; no official duration exists for this plan (the documentation gives none; a request is not documented as held). An optional warm-up (a scheduled request, or minimum replicas 1) would cost about USD 1.4 to 3.4 in the window and needs a separate decision.

**Image.** Public image on GitHub Container Registry built by a GitHub Actions workflow with the built-in `GITHUB_TOKEN` (`packages: write`), tagged with the commit SHA, linked to the repository with `LABEL org.opencontainers.image.source`. A new package is private and must be made public once by hand (irreversible); test an anonymous `docker pull`. The Container Apps documentation contradicts itself on whether a public image needs `az containerapp registry set --server ghcr.io` (without credentials); try the plain create first. No Azure Container Registry. Deployment is done by the owner from a local `az login`; no Azure identity in CI.

**Speech.** Unchanged and independent of the host: the page can only speak 140 distinct sentences (7,141 characters); pre-generate them once as mp3 (about 3 MB) so the public app holds no Speech key and has no quota to exhaust. Generate on a paid tier because the output-rights clause appears to be reserved to paid-tier customers (to be read in the original): the existing AIServices S0 account, about USD 0.10, after one test request; show a visible note that the voice is synthetic. Without this step the page keeps its browser voice only.
